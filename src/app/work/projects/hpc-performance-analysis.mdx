A university project in high-performance computing. The task was to take a parallel C++
application, work out where it spent its time, and make it faster.

I profiled it two ways that answer different questions. TAU instruments the code at the function
level and shows where the time goes: per-function exclusive time across the MPI ranks. Linux
`perf` reads the hardware counters and shows why, in terms of cache misses, branch mispredictions
and instructions per cycle. On top of that I wrote a bit of Python to render each rank's exclusive
time as a heatmap, which makes load imbalance obvious at a glance rather than buried in a table of
numbers.

Most of what came out of it was about memory access patterns. Reordering a couple of loops and
partitioning the work by size cut the runtime by about a third.
