Running your own cloud sounds like a weekend project. In my case it turned into a proper little infrastructure: Nextcloud, Vaultwarden, n8n, Dawarich and a few more containers, all restricted to a Tailscale mesh so they're never exposed to the open internet. This post covers the Nextcloud piece specifically: getting it running reliably behind Tailscale with SSL from Let's Encrypt.

## Why Tailscale instead of a public reverse proxy

The tempting path is to put a reverse proxy on a public VPS, forward traffic, and get automatic HTTPS. I tried that. The problem: your files and your password manager are accessible to anyone who can reach that IP. Even with strong passwords, you're one misconfigured firewall rule away from trouble.

Tailscale solves this by making your services reachable only to devices enrolled in your tailnet. No public IP, no open ports. The tradeoff: you can't share links with people outside your tailnet, which is fine for a personal setup.

## Prerequisites

- Ubuntu server
- Docker and Docker Compose installed
- Tailscale installed and authenticated on the server
- A domain name (e.g. `nextcloud.home.example.com`) with DNS pointing to your Tailscale IP

### Get your Tailscale IP

```bash
tailscale ip -4
# → 100.x.x.x
```

Add an A record in your DNS provider pointing your chosen hostname to that IP. Because this is a private IP, only devices in your tailnet will be able to resolve it to something reachable.

## Docker Compose setup

```yaml
version: "3.9"
services:
  nextcloud:
    image: nextcloud:latest
    restart: unless-stopped
    environment:
      - MYSQL_HOST=db
      - MYSQL_DATABASE=nextcloud
      - MYSQL_USER=nextcloud
      - MYSQL_PASSWORD=${NC_DB_PASSWORD}
      - NEXTCLOUD_TRUSTED_DOMAINS=nextcloud.home.example.com
    volumes:
      - nextcloud_data:/var/www/html
    depends_on:
      - db

  db:
    image: mariadb:latest
    restart: unless-stopped
    environment:
      - MYSQL_ROOT_PASSWORD=${DB_ROOT_PASSWORD}
      - MYSQL_DATABASE=nextcloud
      - MYSQL_USER=nextcloud
      - MYSQL_PASSWORD=${NC_DB_PASSWORD}
    volumes:
      - db_data:/var/lib/mysql

volumes:
  nextcloud_data:
  db_data:
```

Note: `NEXTCLOUD_TRUSTED_DOMAINS` must exactly match the hostname you'll use. Nextcloud blocks requests from unrecognised hosts, and this caught me off guard the first time.

## HTTPS with Caddy

I put Caddy in front as the reverse proxy. It terminates TLS and routes to the container, and the nice part is that it manages the certificate itself: no certbot, no renewal cron to forget about. A minimal Caddyfile is just:

```caddyfile
nextcloud.home.example.com {
  reverse_proxy localhost:8080
}
```

Caddy also sets the `X-Forwarded-*` headers on its own, so Nextcloud sees the right protocol without any extra config.

### The certificate challenge

Here's the non-obvious part: the usual HTTP-01 challenge needs a publicly reachable server, and mine isn't public. The DNS-01 challenge gets around that by proving domain ownership through a TXT record instead of an HTTP endpoint. Caddy can do this directly, as long as you build it with your DNS provider's plugin and give it an API token that can write TXT records:

```caddyfile
nextcloud.home.example.com {
  reverse_proxy localhost:8080
  tls {
    dns <your-provider> {env.DNS_API_TOKEN}
  }
}
```

Replace `<your-provider>` with your DNS provider's module (e.g. `cloudflare`, `godaddy`).

## Nextcloud config tweaks

After the first login, Nextcloud will likely warn about a few missing config values. Edit `/path/to/nextcloud/config/config.php`:

```php
'overwriteprotocol' => 'https',
'overwritehost'     => 'nextcloud.home.example.com',
'trusted_proxies'   => ['127.0.0.1'],
```

Without `overwriteprotocol`, Nextcloud generates `http://` URLs for WebDAV and caldav even when your clients are connecting over HTTPS. Sync clients then fail silently.

## Background jobs

Nextcloud's background jobs (thumbnail generation, activity cleanup, etc.) default to AJAX mode, which only runs when someone has the web UI open. Set them to cron:

```bash
# On the host, not inside the container
* * * * * docker exec <nextcloud-container-name> \
  php -f /var/www/html/cron.php
```

The container name depends on your Compose project name. Check with `docker ps`.

## Result

After all this: Nextcloud is accessible from any device in my tailnet, syncing contacts, calendars, and files. The private IP means it never appears in any internet scan. Caddy renews the certificate on its own, well before it expires.

Total monthly cost: electricity for the server and the domain name.
